## Что делает

Вид «Дерево» в боковой колонке показывает файлы репозиториев и сам их читает: раскрытие каталога - клик, стрелка вправо, Enter или пробел. Строка корня несёт подпись и подсказку, ветку (`⎇ main`) и число изменённых путей (`±3`). У строки файла - отметка git: `M` изменён, `A` добавлен, `D` удалён (удалённый файл остаётся строкой), `R` переименован, `U` не отслеживается, `!` конфликт; у каталога с отметкой внутри стоит `•`.

- **Области.** Дерево принадлежит либо проекту (репозитории выбранного проекта), либо сессии (её корень первым, затем остальные репозитории проекта). Вкладки областей появляются, когда у плагина `sessions` есть живая сессия. Раскрытые каталоги и свёрнутые корни помнятся отдельно у каждой области: раскрытие в одной сессии другую не меняет. Ушла сессия в worktree - её корень становится worktree с подписью «репозиторий ⎇ worktree», вышла - область исчезает.
- **Без опроса.** За каждым раскрытым корнем следит одно рекурсивное слежение (`fs.watch`): в простое плагин не делает ни одного вызова. Свёрнутый корень не стоит ни слежения, ни чтения каталогов; его ветка и число изменений обновляет сообщение `git` об индексе и голове. После лавины событий (checkout) и по кнопке «Обновить» раскрытые каталоги перечитываются целиком: ОС теряет часть событий.
- **Перетаскивание.** Любая строка (корень, каталог, файл) - источник перетаскивания: вид отдаёт ядру её абсолютный путь (`ctx.drag.start`), терминал вида `sessions` вставляет его в кавычках оболочки.
- **Смена ветки.** Клик по ветке в строке корня открывает меню с поиском (стрелки, Home, End, Enter, Escape). Отказ приходит от `git` и показан в меню: в репозитории работает сессия, фильтры в конфиге, конфликт с незакоммиченной правкой. У worktree сессии ветка без кнопки: ею управляет сессия.

## Контракты и команды

Плагин ничего не отдаёт другим плагинам: он владелец контракта `cyborg.tree-decoration` (рисует то, что отдают поставщики), а корни и ветки берёт у соседей. Без любого из них дерево работает.

| Контракт | Как берётся | Без него |
|---|---|---|
| `cyborg.tree-decoration` ^1 (кратность many) | `consumes`: отметки от всех поставщиков (`git` и другие); более значимая отметка на путь побеждает (конфликт, неотслеживаемый, добавленный, переименованный, удалённый, изменённый) | Дерево без отметок |
| `cyborg.projects` ^1 | `optional`: репозитории выбранного проекта и корни сессии (`roots`) | Вместо дерева проекта пояснение; корень сессии - её каталог |
| `cyborg.sessions` ^1 | `optional`: события `onChange` (`cwd`, `exit`) ведут области сессий; `uses` определяет репозиторий запуска, если он есть (поставщик старше 1.2 его не даёт - тогда репозиторий запуска определяется по каталогу) | Только область проекта |
| `cyborg.git` ^1 | `optional`: корень каталога (`root`), ветка (`branch`), список веток и смена (`branches`, `switch`, нужна версия 1.1); каждый член проверяется перед вызовом | «не git» вместо ветки, меню недоступно |

Типы `cyborg.projects`, `cyborg.sessions` 1.2 и `cyborg.git` 1.1 временно лежат в [`contracts/`](https://github.com/dex-it/cyborg-plugins/tree/master/contracts) этого репозитория.

Команды открыты только виду (человеку), другим плагинам закрыты:

| Канал ai-cyborg | Команда | Что делает |
|---|---|---|
| `fs:list` | `files.list(dir)` | Записи каталога `{ name, kind, link? }`: без `.git`, каталоги раньше файлов, внутри групп по имени. Любой каталог в `workspace`, вне него - отказ шлюза |
| - | `files.view(область?, обновить?)` | Снимок дерева для вида: корни, раскрытые каталоги, отметки, ветки, области |
| - | `files.expand(dir)`, `files.collapse(dir)`, `files.toggle-root(корень)` | Раскрыть и свернуть; каждая отвечает свежим снимком |
| - | `files.open(file)` | Открыть файл в просмотре: команда `viewer.open` плагина `viewer` (M-10) |
| - | `files.branches(корень)`, `files.switch(корень, ветка)` | `cyborg.git.branches` и `switch` для корня дерева |
| - | `files.stats` | Диагностика: сколько вызовов шлюза сделало дерево |

Соответствие записано в `CHANNELS` (`index.ts`) и проверяется тестом. Главная часть сообщает виду `{ changed: версия }` по каналу вида; вид сам просит снимок, ответ старее показанного отбрасывает.

## Права

Одно право: **читать файлы в `workspace`** (репозитории проектов). Оно же открывает слежение. Записывать файлы и запускать программы плагину не нужно: git вызывается через контракт, а не напрямую. Границу держит шлюз ядра, плагин добавляет свою проверку формы пути: абсолютный, без `.`, `..` и NUL (строка `/repo/link/..` внутри репозитория после раскрытия ссылки вышла бы наружу).

## Не выходит за workspace

Тесты (`test/list.test.ts`): `..` и `.` в пути, относительный путь, корень файловой системы, домашний каталог, сосед с общим префиксом имени, ссылка внутри репозитория на каталог снаружи, `/repo/link/..`, репозиторий убран из проекта. Символьные ссылки: цель внутри `workspace` показана как цель (каталог раскрывается), цель снаружи или висячая - строка-ссылка без раскрытия. В ai-cyborg ссылка наружу читалась (`AllowedPaths` сверял строку); ядро всегда раскрывает ссылки, поэтому такой каталог закрыт - сознательное ужесточение (пилот PL-04, решения ядра).

## Отличия от ai-cyborg

- Дерево не опрашивает git раз в 5 секунд: отметки и ветка обновляются по событию `git` (индекс, голова) и по событиям слежения за файлами. Окно без фокуса ничего не тратит; показ вида после скрытия перечитывает всё.
- Область определяется не вкладкой: активная вкладка плагину неизвестна. По умолчанию это сессия, от которой событие пришло последним, иначе проект; выбор человека закрепляется до выхода сессии.
- Запись каталога называет род (`kind`), а не `isDir`; у отметки git восемь значений вместо одной буквы.
- Вкладка просмотра открывается плагином `viewer` (M-10), а не окном дерева.

## Ограничения

- **Удалённые клоны (`remote-sessions.fs`) не показаны.** Нужны идентификатор удалённой сессии и каталоги её клонов; `cyborg.sessions` не отдаёт ни того, ни другого, и плагину неоткуда их узнать. Чтобы вид читал клон «только на чтение», нужен член `cyborg.sessions` (какие корни и какого хоста у сессии) - вынесено в хвост.
- **Сессия без событий неизвестна.** Контракт `cyborg.sessions` не перечисляет живые сессии и не называет рабочий каталог запуска: плагин узнаёт сессию по первому событию (активность, ожидание, смена каталога). Свежая молчащая сессия видна в дереве проекта, но не отдельной областью. Нужны члены `list` и `active` в `cyborg.sessions`.
- **Перетаскивание в окне не проверено.** Ядро (`view:drag`, `resolveDragFile`) принимает сегодня путь от корня рабочей папки и только файл; абсолютный путь и каталог оно отклоняет. Вид отдаёт абсолютный путь и для каталогов, как делал ai-cyborg, поэтому до доработки ядра бросок в окне может не доходить. Тесты проверяют вид, путь и вставку на стороне `sessions`, а не `webContents.startDrag`.
- **Линукс: `fs.inotify.max_user_watches`.** Рекурсивное слежение ставит inotify на каждый каталог раскрытого корня; при нехватке предела слежение не открывается: корень читается, на строке корня предупреждение, «Обновить» пробует снова. Запасного опроса нет.
- Слежение не заходит в каталоги по символьным ссылкам: их содержимое обновляется «Обновить» и после лавины.
- Просмотр и поиск файлов (`viewer`, `search`) - отдельные плагины; дерево только читает и ничего в репозитории не меняет.
- Вид проверен тестами на настоящем ядре с подменённым DOM; настоящий фрейм, элементы `cy-*` и перетаскивание проверяет окно приложения.

## Проверка бюджетов

Критерий задачи: событие `fs.watch` доходит до вида не позже 5 мс на p99 сверх склейки ядра в 50 мс. Тест (`test/budget.test.ts`) меряет цену дерева как время от начала обработки пачки событий до сообщения виду (`lastBatchAt` в `files.stats`) и печатает ещё время от конца записи до вида и до голого слушателя того же каталога. В общем прогоне (`npm test`, CI) он мягкий: допуск 30 мс на p99 и 15 мс на p50, 40 замеров; он ловит только грубую регрессию, потому что раннер CI шумит сильнее допуска. Строгий режим:

```bash
cd plugins/code/files && CYBORG_BUDGET=strict node --test test/budget.test.ts
```

Допуск строгого режима: 5 мс на p99 и p50 цены дерева, до трёх попыток на замер; `files.list` не хуже голого `fs.list` на 10% по медиане (плюс 3 мс шума вызова). Числа строгого прогона на тихой машине - в описании PR.
