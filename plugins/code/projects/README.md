## Что делает

Проект - набор локальных репозиториев под одним именем; от него зависят сессии, дерево файлов, git, поиск и трекеры. Плагин хранит проекты воркспейса, помнит выбранный проект и показывает два вида:

- **«Проекты»** - список проектов, выбор кликом, «Новый проект…», «Свойства…» и «Удалить» (с вопросом через слой диалогов ядра);
- **диалог свойств проекта** (модальное окно): название, описание, репозитории с порядком («Папка…», «Выше», «Ниже», «Убрать») и секции других плагинов - например, источники задач от `trackers`. Название обязательно, отказ проверки показан в окне, закрыть окно с несохранённой правкой можно только после вопроса.

В меню «Воркспейс» плагин добавляет «Новый проект…» и «Свойства проекта…» (второй доступен, пока проект выбран).

Каталог, выбранный кнопкой «Папка…», сразу становится областью `workspace` для остальных плагинов (`files`, `git`, `search`), ещё до сохранения проекта; сохранённые репозитории всех проектов остаются в ней.

## Контракты и команды

Типы контрактов временно живут в [`contracts/`](https://github.com/dex-it/cyborg-plugins/tree/master/contracts) этого репозитория и переедут в пакет ядра ([cyborg-harness#256](https://github.com/dex-it/cyborg-harness/issues/256)).

- **Отдаёт `cyborg.projects` 1.0**: `list`, `selected`, `hasSelected` (источник `enabled` для пункта меню), `roots` (корни дерева файлов сессии: свой корень первым, затем остальные репозитории проекта) и `onChange` (проект добавлен, изменён, удалён, выбран другой).
- **Собирает `cyborg.project-settings` ^1** (кратность many): каждый поставщик описывает секцию формы (`section`), отдаёт значения (`load`), проверяет (`validate`) и записывает (`save`). Проект не сохраняется, пока хоть один поставщик отвечает ошибкой; после записи проекта секции сохраняются у поставщиков. Так раньше `saveProjectsState` проверял источники задач и сбрасывал вход трекеров.
- **Команды.** Другим плагинам открыты `projects.new`, `projects.edit` и `projects.select` (выбор проекта по идентификатору, пустая строка снимает выбор). Остальные команды - для видов плагина.

Каналы владельца ai-cyborg заменены командами; соответствие записано в `CHANNELS` (`index.ts`) и проверяется тестом:

| Канал ai-cyborg | Команда | Что делает |
|---|---|---|
| `dialog:pickDir` | `projects.pick-dir` | Диалог выбора каталога; ответ - физический путь, отмена - `null`; каталог сразу уходит ядру как корень |
| `projects:load` | `projects.load` | Проекты, выбранный проект и замечание |
| `projects:problem` | `projects.problem` | Замечание словами: что случилось, где исходные байты, что делать |
| `projects:save` | `projects.save` | Проверка, запись, корни ядру, секции поставщиков |
| `project:selected` | `projects.select` | Выбранный проект (и `selected`, `hasSelected`, `onChange` контракта) |

Ещё: `projects.form` (данные диалога свойств), `projects.remove` (удаление проекта), `projects.new` и `projects.edit` (меню).

## Права

- **Читать файлы в `granted`** (выбранное человеком в диалоге): чтобы получить физический путь выбранного каталога и репозитория проекта (`realpath`: git и Claude Code называют репозиторий им, FR-5007). Без этого путь через символьную ссылку (`/tmp` и `/var` на macOS) разошёлся бы с репозиторием. Читать содержимое файлов плагину не нужно.
- **Задавать корни проектов (`security.roots`)**: репозитории проектов и выбранные каталоги плагин отдаёт ядру, и они становятся областью `workspace` для остальных плагинов. Ядро не принимает корень, названный только в присланном файле воркспейса, пока человек не выбрал его в диалоге или не назвал в файле пользователя: такой каталог плагин покажет в замечании, а остальные корни примет.
- Диалог выбора каталога, `config` и `state` прав не требуют. Записи вне своих разделов плагин не просит.

## Настройки

- Раздел `config` (`settings.projects` файла воркспейса, слой воркспейса): `items` - список проектов `{ id, name, description, repos }`; `repos` - абсолютные физические пути в порядке проекта (FR-10004). Схема - `config.schema.json`.
- Раздел `state` (память воркспейса): `lastProjectId` - выбранный проект.

Раздел, не прошедший схему, отказывает только этому плагину: причина попадает в журнал ядра, остальные плагины работают. Повреждённый файл воркспейса не роняет окно: ядро хранит копию `<файл>.corrupt-<время>` и отменяет запись, плагин при попытке сохранить сообщает причину и не затирает файл.

## Ограничения

- Секции источников задач и Jira и поля SSH-хостов проекта (раньше часть `Project`) - у `trackers` (M-13) и `remote-sessions` (M-05); плагин только показывает их секции в форме. Поставщика секции нет - в форме их нет.
- Замок воркспейса, «Недавние», выбор воркспейса при старте и окно создания воркспейса - ядро и приложение; из workspace-text.ts перенесён только текст замечания о файле.
- Причину порчи файла плагин узнаёт при отказе записи: при открытии ядро не сообщает плагину, что файл не разобран. Путь копии `.corrupt-<время>` плагину неизвестен: замечание называет шаблон имени.
- Физический путь определяется при сохранении и выборе каталога; путь, не выбранный в диалоге и не лежащий в `granted`, остаётся как задан, а отказ шлюза виден в журнале (`denied`). Прежних файлов ai-cyborg (`projects.json`, `trackers.json`) плагин не читает: решение D-00 о чистом листе.
- Символьная ссылка внутри репозитория на каталог вне него шлюзом ядра закрыта; в ai-cyborg такой путь читался как и в самом репозитории.
- Вид проверен тестами на настоящем ядре с подменённым DOM; настоящий фрейм и элементы `cy-*` проверяет окно приложения.
