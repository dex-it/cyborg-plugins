## Что делает

Все обращения к `git` идут через этот плагин: остальным плагинам (`files`, `viewer`, `search`, `trackers`, кнопки команд) право `process` на `git` не нужно, они берут сведения у контракта. Плагин отдаёт:

- корень рабочего дерева каталога, имя текущей ветки, список файлов под корнем (без игнорируемых `.gitignore`), адреса remote;
- статус: ветка, отслеживаемая ветка, расхождение с ней, изменения по двум буквам `git status --porcelain=v1` (индекс и рабочее дерево), переименования с исходным путём;
- содержимое файла в HEAD: для сравнения в просмотре; двоичный файл, новый и больше 5 МиБ - `null`;
- список веток (локальные свежие первыми и ветки remote без локальной копии) и смену ветки;
- событие «изменился индекс, голова или ветка»: вместо опроса раз в 3 секунды, как в ai-cyborg;
- отметки git у строк дерева файлов (`cyborg.tree-decoration`).

Плагин безопасно работает с чужими репозиториями: конфиг репозитория из каталога человека недоверенный.

## Контракты

Типы временные и переедут в пакет ядра вместе с [cyborg-harness#258](https://github.com/dex-it/cyborg-harness/issues/258).

- **Отдаёт `cyborg.git` 1.1.** В `@cyborg-harness/contracts` у контракта пока `status` и `onChange`; остальные семь членов объявляет расширение `GitV11` в [`contracts/`](https://github.com/dex-it/cyborg-plugins/tree/master/contracts) этого репозитория (решение D-00, п. 11, как `SessionsV12`). Потребитель берёт поставщика как `Remote<GitV11>` и проверяет, что нужный член есть: поставщик 1.0 их не даёт; потребителю, которому член обязателен, достаточно `requires: { "cyborg.git": "^1.1" }`.
- **Отдаёт `cyborg.tree-decoration` 1.0** (`marks`, `onChange`): одна отметка на путь - конфликт, неотслеживаемый, добавленный, переименованный, удалённый, изменённый; рисует владелец дерева (`files`). Первый вопрос об отметках корня открывает слежение за `.git`.
- **Берёт при наличии `cyborg.projects` ^1 и `cyborg.sessions` ^1.** Цикла в графе нет: `sessions` о `git` не знает.

| Канал ai-cyborg | Член `cyborg.git` | Что делает |
|---|---|---|
| `git:root` | `root(dir)` | Корень рабочего дерева каталога; не репозиторий - `null` |
| `git:branch` | `branch(root)` | Имя ветки; голова отсоединена - `HEAD`; репозитория или коммитов нет - `null` |
| `git:status` | `status(repo)` | Статус; не репозиторий - `null` (в ai-cyborg пустой объект) |
| `git:branches` | `branches(root)` | Текущая, локальные и только удалённые ветки; только репозитории проектов |
| `git:switch` | `switch(root, branch)` | `{}` - ветка сменилась, `{ error }` - отказ с причиной; только репозитории проектов |
| `git:headContent` | `headContent(file)` | Текст файла в HEAD или `null` |
| - | `remotes(root)`, `files(root)`, `onChange(repo, listener)` | Адреса fetch-remote, файлы под корнем, событие изменения `.git` |

Соответствие записано в `CHANNELS` (`index.ts`) и проверяется тестом. Каждый член с путём объявлен с `guard` `fs.read` на первый аргумент: вызывающий без права читать каталог сведений о нём не получает, а права вызывающего не расширяют права самого плагина.

## Смена ветки

Ветка меняется единственной командой `git switch -- <ветка>` (с `-c submodule.recurse=false`) и только по имени из списка веток, поэтому имя не может стать флагом. Отказ с причиной в `{ error }`, если:

1. репозиторий не входит в проект (`cyborg.projects`): рабочие каталоги живых сессий и worktree меняет сама сессия; без плагина `projects` ветки и смена отказывают;
2. **в репозитории работает сессия** (`cyborg.sessions.uses`, FR-7003): «в репозитории работает сессия Claude: веткой управляет она». Сессий в приложении нет совсем - ветка меняется; поставщик сессий старше 1.2 без `uses` ответить не может, и смена отказывает;
3. **в конфиге репозитория (слои `local` и `worktree`) есть `filter.*`, `extensions.partialClone` или `remote.*.promisor`** (FR-7004): выписывание файлов запустило бы smudge-фильтр или докачку транспортом из конфига. Ветку тогда меняют в терминале. Фильтры из пользовательского и системного конфига доверенные и ветку не блокируют;
4. git отказал сам (конфликт с незакоммиченной правкой и прочее): причина - первая строка его ответа.

## Безопасность запусков

Каждый запуск начинается с `--no-optional-locks -c core.fsmonitor=false -c core.hooksPath=/dev/null`: команда из `.git/config` (fsmonitor) и хуки не запускаются, чтение не пишет в индекс и не будит собственное слежение. Драйверы фильтров `filter.*.clean|process|required` из конфига репозитория и вложенных репозиториев (подмодулей, до глубины 8) `git status` исполнил бы, а одним ключом их не отключить: перед `status` плагин собирает ключи (`config`, `ls-files`) и перекрывает их переменными `GIT_CONFIG_COUNT`, `GIT_CONFIG_KEY_*`, `GIT_CONFIG_VALUE_*`. Не удалось собрать ключи полностью (путь или имя не в UTF-8 - в том числе у незаполненного подмодуля: проверить его по строке нельзя, а пропуск дал бы запуск его фильтра, ai-cyborg отказывал только для заполненного; слишком глубокая вложенность) - `status` отказывает, а не запускается без перекрытия. Содержимое HEAD читается как `cat-file blob`: ни textconv, ни smudge-фильтр не запускаются.

## Права

- **Читать файлы в `workspace`** (репозитории проектов и рабочие каталоги живых сессий): рабочий каталог запуска git и слежение за `.git` проверяются как чтение. Записывать файлы плагину не нужно.
- **Запускать `git`** с закреплёнными аргументами - по одному правилу на каждую команду (12 правил: `status`, `config` для ключей фильтров и для проверки смены ветки, `ls-files` двух видов, `rev-parse` двух видов, `cat-file` двух видов, `remote -v`, `for-each-ref`, `switch`). Любая другая подкоманда и любое другое начало командной строки отклоняются шлюзом до запуска. В хвосте запрещены флаги, подменяющие конфиг, каталог и исполняемые программы (`-c`, `-C`, `--config-env`, `--git-dir`, `--work-tree`, `--exec-path`, `--output`, `--ext-diff`, `--textconv`), у `switch` ещё `--force`, `--orphan`, `--detach`, `--discard-changes` и другие. Переменные окружения: `GIT_CONFIG_*` только у `status`, `LC_ALL` только у запросов ключей конфига. Право «запускает программы» остаётся полным доступом через программу: запрет флагов смягчает его, но не отменяет.

Плагин из поставки: `cyborg.git` отдают только такие плагины.

## Слежение вместо опроса

`onChange(repo, listener)` срабатывает, когда в `.git` меняются индекс, голова, упакованные ссылки или состояние слияния и перебазирования, и когда меняются ссылки веток в `refs/heads` (`git add`, `commit` в том числе пустой и `-a`, `checkout`, смена ветки самим плагином, ветка, созданная или удалённая снаружи). Правка файлов рабочего дерева и `fetch` сюда не входят: о правке файла знает тот, кто следит за деревом. Для worktree и подмодуля `.git` - файл с `gitdir:`, слежение идёт за указанным в нём каталогом и за общим `refs/heads` (из `commondir`), если они читаемы (лежат в `workspace`). Оповещение идёт без собственной задержки: пачку событий ядро склеивает само за 50 мс. Репозиториев под слежением не больше 16 (по два слежения на репозиторий из 64 на плагин), слежение за репозиторием - одно на всех подписчиков и снимается с последней отпиской или выгрузкой плагина. Ядро начинает доставку событий позже возврата `watch` (FSEvents на macOS, нагруженный раннер): событие, наступившее в первые миллисекунды после подписки, может не прийти, поэтому потребитель, которому нужно состояние сейчас, читает его сам после подписки. Параллельные `status` одного репозитория склеиваются: не больше двух запусков на пачку, и последний видит правку, сделанную во время первого.

## Отличия от ai-cyborg

- `status` отвечает `null` вне репозитория и отказом, если ключи фильтров собрать не вышло; ai-cyborg в обоих случаях отдавал пустой объект, скрывая от потребителя, что статус неизвестен. Буква на путь ai-cyborg выводится из двух букв (рабочее дерево главнее индекса); тест фиксирует соответствие.
- Режим `--untracked-files=all` сохранён: неотслеживаемые файлы названы по одному, а не каталогом.
- Отказ смены ветки при сессии и в `filter.*` приходит `{ error }`, как раньше из канала `git:switch`; чужой репозиторий и неверные аргументы - исключение, как «Некорректные аргументы» раньше.
- Новое сверх ai-cyborg: слежение за каталогом worktree и подмодуля, оповещение вместо опроса, `cyborg.tree-decoration`.

## Ограничения

- `git-search.ts` (`git grep` и поиск среди изменений) в плагин не перенесён: это задача `search` (M-12). Остаётся ли у него право `process` на `git` или члены уйдут в контракт, решает она; сейчас члена «поиск» в `cyborg.git` нет.
- `gitOriginUrl` (`remote get-url origin`) в контракт не вошёл: `remote-sessions` берёт адрес через `remotes`; отдельного члена задача не требует.
- Версия `cyborg.git` 1.1 с расширением `GitV11` временная: когда ядро объявит члены ([cyborg-harness#258](https://github.com/dex-it/cyborg-harness/issues/258)), типы переедут, а имена могут измениться.
- Работа с путями рассчитана на `/` (macOS и Linux).
- Слежение не видит `fetch` (ссылки `refs/remotes`): список веток remote читается при открытии меню, а не по событию. Ветка в подкаталоге `refs/heads/feat/x`, созданная в уже существующем подкаталоге, оповещения не даёт (ядро следит за каталогом без рекурсии); создание подкаталога даёт.
- `status` в репозитории с очень большим числом изменений ограничен выводом 64 МиБ: больше - отказ.

## Проверка бюджетов

Бюджет D-00, п. 9 (не хуже базы ai-cyborg на 10% по медиане; `onChange` не позже 5 мс на p99 после склейки ядра в 50 мс) принят как цель и измеряется строго на тихой машине (`test/budget.test.ts`). В общем прогоне (`npm test`, CI) тест мягкий: 40 замеров, медиана минимумов пачек по пять, допуск «не хуже вдвое плюс 5 мс» и 30 мс на p99 у `onChange`, числа печатаются в вывод; он ловит только грубую регрессию, потому что раннер CI шумит сильнее допуска. Строгий режим включается переменной окружения:

```bash
cd plugins/code/git && CYBORG_BUDGET=strict node --test test/budget.test.ts
```

В нём допуск 10% по медиане (плюс 3 мс шума запуска процесса) и 5 мс на p99, до трёх попыток на замер. Результаты строгого прогона на тихой машине - в описании PR.
