## Что делает

Плагин переносит фичу 17 ai-cyborg: `claude` работает не на вашей машине, а на SSH-хосте из `~/.ssh/config`, а окно, терминал и просмотр остаются у человека. Репозитории проекта клонируются на хост, агент запускается под демоном `agentd` (Node, один на пользователя хоста), демон держит процесс и последний мегабайт вывода. Закрытая вкладка или оборванная сеть сессию не убивают: она подхватывается заново и показывает прежний вывод; без дела в ожидании она засыпает через 2 часа и просыпается из «Истории».

Что получает человек:

- в свойствах проекта секция «Удалённые хосты (SSH)»: до 32 алиасов `~/.ssh/config`;
- проверка хоста (Linux, `node` 18+, `git`, `claude`, `script`, вход Claude либо токен) и установка демона по `ssh host sh -s` с проверкой `sha256`;
- создание сессии: клоны репозиториев проекта, ветка, `claude` в `script` под демоном; терминал открывает потребитель контракта `cyborg.agent` (плагин `sessions`);
- подхват после обрыва по `resumeId` с прежним выводом из кольца демона, сон и пробуждение, «История» спящих сессий проекта;
- чтение клонов на хосте без правки (список, содержимое, ветка, статус, поиск) - команды `remote-sessions.fs` и `remote-sessions.search`;
- место на хосте и удаление оставленных клонов (`disk`, `purge`);
- токен `claude setup-token` для входа агента на хосте без `claude auth login`: в хранилище секретов ядра.

## Как это устроено на ядре

В ai-cyborg приложение держало один долгоживущий `ssh` со строчным протоколом JSON и само рисовало терминал. На ядре у плагина нет долгоживущего процесса со стримингом ([cyborg-harness#260](https://github.com/dex-it/cyborg-harness/issues/260)): `ctx.os.process.run` ждёт завершения, а `pty` смешивает потоки. Поэтому протокол демона (PROTO 2, сообщения те же) идёт двумя короткими способами, а демон на хосте не меняется:

- **запросы** - один `ssh host sh .cyborg/agentd/<версия>/client.sh rpc` на пачку: строки JSON уходят в stdin через `ctx.os.process.run`, ответы с `rid` читаются из stdout. Состояния канала и переподключения нет: обрыв - ошибка вызова;
- **терминал** - `launch` возвращает описание запуска `ssh -tt <хост> sh .cyborg/agentd/<версия>/client.sh attach <sid> <экземпляр>`; запускает его в своём `pty` потребитель, ввод и вывод идут через него. `attach` (новый файл `client.js`) печатает вывод демона, шлёт ввод и размер терминала; закрытие вкладки обрывает только `ssh`;
- **события** - хуки `claude` на хосте пишут `~/.cyborg/sessions/<sid>/events.jsonl`; `watch` читает файл опросом раз в 2 секунды (`tail -c +N` по `ssh`) и переводит строки теми же правилами, что `agent-claude-code`.

Демон (`src/agentd/` ai-cyborg) лежит в `companions/agentd/` репозитория без правок; добавлен только `client.ts`. Собирается esbuild в два файла (`npm run build:companions` -> `assets/agentd/*.js.txt`, затем `npm run embed-assets -- plugins/sessions/remote-sessions`), плагин вшивает их в `index.mjs`. Тесты проверяют, что ресурсы свежи относительно `companions/`, а числа плагина (32, 4, 2 ч, 1 МиБ, PROTO) совпадают с исходником демона.

## Контракты и команды

Плагин отдаёт `cyborg.agent` 1.0 (`capabilities`: `resume`, `history`, `events`) и `cyborg.project-settings` 1.0 (секция `ssh`, поле `hosts`); `cyborg.projects` берёт, если он есть (`optional`).

| Член `cyborg.agent` | Что делает |
|---|---|
| `facts` | Находит `ssh` (`ssh -V`), отдаёт версию |
| `launch` | С `resumeId` вида `<sid>@<хост>`: проверяет хост, будит спящую сессию, отдаёт запуск `ssh -tt ... attach`. Без него - запуск, который печатает причину и выходит кодом 2 (создать сессию нужно командой `remote-sessions.create`) |
| `watch` | События хуков claude с хоста опросом: `cwd`, `session` (с `resumeId` вида `<sid>@<хост>`), `activity`, `prompt`, `turnEnd`, `waiting`. Подхваченная живая сессия читается с конца файла: прошлое уже показано |
| `ended` | Код 127 - `notFound`; обрыв `ssh` (255) сбоем агента не считается: сессия на хосте жива |
| `history` | Спящие сессии проекта каталога на его хостах; недоступный хост не держит ответ дольше 8 секунд |

Каналы владельца ai-cyborg -> команды плагина:

| Канал | Команда | Кому открыта |
|---|---|---|
| `remote:create` | `remote-sessions.create <проект> {host, repo, branch}` | плагинам |
| (spawn_agent) | `remote-sessions.create-task <проект> {host, repo, branch, prompt}` | плагинам |
| `remote:discover` | `remote-sessions.discover <проект>` | плагинам |
| `history:remote` | `remote-sessions.history <проект>` | плагинам |
| `remote:wake` | `remote-sessions.wake <проект> <хост> <sid>` | плагинам |
| `remote:remove-asleep` | `remote-sessions.remove-asleep <проект> <хост> <sid>` | человеку (виду) |
| `remote:disk` | `remote-sessions.disk <проект> <хост>` | человеку (виду) |
| `remote:purge` | `remote-sessions.purge <проект> <хост> <sids> [force]` | человеку (виду) |
| (закрытие вкладки, close_agent) | `remote-sessions.close <resumeId> [keep]` | плагинам |
| `remote:fs` | `remote-sessions.fs <resumeId> <операция> <путь>` | плагинам |
| `remote:search` | `remote-sessions.search <resumeId> <text|changes> <запрос>` | плагинам |
| `remote:claude-token:status`, `:set`, `:clear` | `remote-sessions.claude-token.status`, `.set <токен>`, `.clear` | человеку (виду) |

`create` и `wake` возвращают `{ resumeId, sid, host, dirs, cwd, roots, notes }`: `resumeId` открывает терминал (`launch({ resumeId })`), `roots` - корни дерева на хосте, `notes` - чего агенту не хватает (`gh`, `glab`, токены). Вместо номера вкладки команды берут `resumeId`: вкладками владеет `sessions`.

## Права

| Право | Зачем |
|---|---|
| `process`: `ssh -T -o BatchMode=yes -o ConnectTimeout=15 -o ServerAliveInterval=15 -o ServerAliveCountMax=3 -o ExitOnForwardFailure=yes --` (env `SSH_AUTH_SOCK`) | Проверка и установка демона, запросы к нему, опрос событий. Без оболочки и без вопросов (BatchMode); алиас стоит после `--`, плагин сверяет его с формой (ведущий «-» ssh принял бы за ключ). **Даёт программе все права пользователя ОС**: через `ssh` можно выполнить на названном хосте любую команду; названные хосты - только из свойств проектов |
| `process`: `ssh -V` | `facts` |
| `process`: `git remote get-url origin` | Адрес origin репозиториев проекта для клонов на хосте. Адрес с учётными данными (`https://user:token@хост/...`) на хост уходит без них |
| `process`: `gh auth token --hostname`, `glab config get token --host` | Токены хостингов origin у gh и glab оператора: уходят демону в stdin ssh, живут только в его памяти и окружении процессов сессии, в `meta.json` и аргументы не попадают. Правила не называют переменных окружения: токены, не привязанные к хосту, до `gh` и `glab` не доходят |
| `launch`: `ssh -tt <те же ключи> --` (env `SSH_AUTH_SOCK`) и `$SHELL -lc '<сообщение об отсутствии цели>'` | Запуск терминала сессии, который исполняет потребитель своим `pty`; ядро сверяет его с этим правом |
| `env`: `SSH_AUTH_SOCK` | Ключи ssh-agent: без него вход по ключу с паролем не работает, а ядро передаёт процессам только PATH, HOME и локаль |
| `fs.read`: `workspace` | Рабочий каталог `git remote get-url origin` - репозиторий проекта |

Токен Claude хранится только в хранилище секретов ядра (`ctx.os.secrets`): не в `config`, `state`, файлах плагина, журнале и аргументах `ssh`. Демону он уходит в stdin и живёт в окружении процессов сессии.

## Настройки

`config`: `hosts` - `{ <id проекта>: [алиасы хостов] }`, слой воркспейса; пишет секция проекта (`cyborg.project-settings`). `state`: `instance` - идентификатор экземпляра Cyborg, по которому демон узнаёт «своё» окно после обрыва.

## Лимиты

| Что | Значение | Где держится |
|---|---|---|
| Хостов в проекте | 32 | `hosts.ts`, проверка формы и числа при сохранении секции |
| Живых сессий на хосте | 4 | демон отвергает пятую; плагин передаёт предел в `spawn` |
| Сон без дела в ожидании | 2 часа | демон; сессия засыпает с клонами и разговором |
| Кольцо вывода для отсутствующего клиента | 1 МиБ | демон; вытесненное заменяется `reset` с режимами терминала |
| Задача и простой агента, порождённого инструментом | 4 часа и 30 минут | передаются демону в `spawn` |

## Как проверено

Тесты идут на `startKernel`: настоящий плагин, **настоящий собранный демон** и подставные `ssh`, `claude`, `uname`, `script` на одной машине («хост» - временный каталог). Проверены: установка и замена демона прежней версии, создание сессии с клоном нужной ветки, ввод в `claude` через терминал и вывод обратно, обрыв `ssh` с подхватом прежнего вывода, события хуков, лимит 4, закрытие и `purge` (грязный клон - только с `force`), чтение клонов и поиск, аргументы с ведущим «-», токен Claude вне журнала, `config` и аргументов `ssh`. Тесты демона из ai-cyborg (`agentd`, `git-auth`, `claude-setup`, `mic` в части arecord) перенесены в `companions/agentd/test`, новые - для `client.js`. Общий набор `agentContractSuite` проходит.

**Настоящий SSH-хост и живой `claude` не проверялись.** Подставной `script` на macOS заменяет util-linux; на Linux CI он тоже подставной, чтобы поведение не расходилось. Запись сцены S21 (V-03) не сверялась.

## Ограничения и отложенное

- **Потоковый процесс** ([cyborg-harness#260](https://github.com/dex-it/cyborg-harness/issues/260)): нет долгоживущего канала, поэтому события приходят опросом раз в 2 секунды (один `ssh` на опрос), а не потоком; нет автоматического переподключения - подхват делает новый `launch` по тому же `resumeId` (его инициирует `sessions`). На хосте с `ControlMaster` в `~/.ssh/config` опрос дешёвый, без него - новое соединение на каждый.
- **Вкладки, стрелка у «Новой сессии» и меню запуска на хосте, диалоги «Место на хостах» и «Вход Claude на хостах»** (`menu:host-disk`, `menu:claude-token`, диалоги) не перенесены: они зависят от `sessions` (M-03, `cyborg.sessions.create` - [cyborg-harness#257](https://github.com/dex-it/cyborg-harness/issues/257)) и видов. Команды для них готовы.
- **Дерево, статус и просмотр удалённых клонов** в плагинах `files`, `viewer`, `git`, `search` (контракты `cyborg.git` и поиска ещё не полны): команды `fs` и `search` отдают данные, подключить их к контрактам потребителей пока нечем.
- **Туннель MCP-сервера `sessions`, `spawn_agent`, `report_done`, `close_agent`, круги работы** (FR-17007..17010) - M-04: нужен сам сервер и обратный туннель `ssh -R`, а правило `process` закрепляет аргументы до `--`. Демон туннель и инструменты поддерживает (сообщения `report`, `close`), плагин их пока не зовёт; `create-task` и `close` готовы под инструменты.
- **Зеркало настройки Claude, доверие к клонам из настройки, память проекта** (FR-17017, `claude-config.ts`) не перенесены; на хост уходит пустое зеркало. Приёмная часть демона перенесена и покрыта тестами.
- **Голосовой ввод** (`mic:started`, `mic:data`, `mic:end`, `/voice`, мост микрофона) отложен по решению владельца (п. 12) из-за [cyborg-harness#261](https://github.com/dex-it/cyborg-harness/issues/261): нужны микрофон кадра вида, поток вид - главная часть и сокет-сервер. Подставной `arecord` демона перенесён вместе с тестами.
- **Автоподхват при запуске** (`discover` + открытие вкладок), уведомления «сессия уснула» и «мало места» (`remote:disk-low`, `remote:report`) - работа `sessions` и видов.
- Демон и плагин версионируются парой: версия каталога на хосте - хеш обоих файлов и скриптов запуска, поэтому правка клиента или скрипта ставит новый каталог, а несовместимый по протоколу демон с живыми сессиями отвергается с числом сессий.
