## Что делает

Когда в одном репозитории работают несколько сессий агента, они мешают друг другу: одна меняет ветку, другая правит те же файлы. Плагин добавляет к системному промпту каждой новой сессии короткую инструкцию, и агент сам уходит в отдельный worktree до первой правки. Окон и кнопок у плагина нет: человек видит результат, когда у сессии появляется свой каталог `<репозиторий>/.claude/worktrees/<имя>` на своей ветке, а дерево файлов идёт за сессией в новый каталог.

## Когда агенту нужен worktree

Инструкция требует `EnterWorktree` перед первой правкой в репозитории, сменой ветки или коммитом; дальше работа идёт только в worktree, а основной каталог остаётся только для чтения. Не требуют worktree файлы вне репозиториев: скрэтчпад и временные файлы. `EnterWorktree` изолирует только репозиторий рабочего каталога сессии, поэтому для репозитория из `--add-dir` инструкция велит завести worktree командой `git worktree add <репозиторий>/.claude/worktrees/<то же имя> -b <та же ветка>` и править файлы только по этому пути.

Решает агент, а не Cyborg: плагин передаёт текст, а исполнение зависит от модели и от версии `claude`, знающей `EnterWorktree`. Без такой версии инструкция остаётся без эффекта, сессия работает без изоляции.

## Контракты и команды

Плагин отдаёт контракт `cyborg.session-prompt` (версия 1.0, поставщиков может быть несколько): метод `fragment()` возвращает текст инструкции. Потребитель (плагин `sessions`) собирает фрагменты всех поставщиков и передаёт их агенту при запуске. Команд, видов и настроек нет.

Текст перенесён из ai-cyborg дословно (константа `ISOLATION_PROMPT` в `src/main/claude-args.ts`, якорный коммит `6fd308f`). Тест сравнивает его побайтно с эталоном `test/fixtures/isolation-prompt.txt`, а при наличии клона ai-cyborg ещё и с исходной константой.

## Права

Не нужны. Плагин не читает файлы, не запускает программ и не ходит в сеть: он отдаёт строку. Так как строку читает агент, контракт `cyborg.session-prompt` доступен только плагинам поставки.

## Как отключить

Уберите `session-isolation` из списка `plugins.enabled` (или не включайте его в набор плагинов приложения): фрагмента изоляции в промпте новых сессий не будет, агент перестанет сам уходить в worktree. Уже запущенные сессии промпт не меняют: он читается при запуске. Остальные плагины от этого не страдают: потребитель без поставщика собирает промпт из оставшихся фрагментов.

## Порядок фрагментов: расхождение с ai-cyborg

В ai-cyborg инструкция изоляции идёт первой, кнопки следующих шагов после неё (`ISOLATION_PROMPT`, пустая строка, `SUGGEST_PROMPT`). Ядро сегодня собирает фрагменты `cyborg.session-prompt` в порядке id плагина-поставщика: `next-actions` стоит раньше `session-isolation`, то есть первыми идут кнопки, а изоляция второй. Явное поле `order` - задача ядра [cyborg-harness#259](https://github.com/dex-it/cyborg-harness/issues/259); пока его нет, расхождение принято как есть, обхода (переименования плагинов и подобного) нет: см. пункт 3 страницы [решений по переносу](/development/decisions/). Тест плагина фиксирует фактический порядок на двух поставщиках через потребителя, устроенного как `sessions`.

## Ограничения

- Сам worktree создаёт агент по инструкции, плагин его не заводит и не проверяет.
- Порядок фрагментов отличается от ai-cyborg до появления `order` в ядре (см. выше).
- Составной промпт целиком и порядок аргументов запуска (`--append-system-prompt`, `--add-dir`) собирают `sessions` и `agent-claude-code`; здесь проверен только вклад изоляции.
- Гашение языкового сервера после `EnterWorktree` и `ExitWorktree` (`lsp-reap.sh` в ai-cyborg) сюда не входит: куда его положить, решает отдельная задача.
