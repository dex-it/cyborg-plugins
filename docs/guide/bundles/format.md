Формат версионирован полем `format`. Сейчас он один: `1`. Незнакомое поле и другое значение `format` - ошибка проверки.

## Исходник: bundles/<id>.json

| Поле | Тип | Обязательно | Что значит |
|---|---|---|---|
| `format` | число | да | Версия формата, сейчас `1` |
| `id` | строка | да | Идентификатор: строчные латинские буквы, цифры и дефис, части через точку допустимы. Совпадает с именем файла |
| `version` | строка | да | Версия бандла `x.y.z`. Повышается, когда меняется состав или версия состава |
| `title` | строка | да | Название для людей |
| `description` | строка | да | Одна-две фразы: для чего набор |
| `extends` | список строк | нет | Идентификаторы бандлов, чей состав включается целиком |
| `plugins` | список строк | да | Идентификаторы плагинов каталога; может быть пустым, если всё пришло из `extends` |

Имя `planned.json` в каталоге `bundles/` занято списком запланированных наборов (`id`, `title`, `summary`, `plugins`); как бандл он не читается.

## Что проверяет `npm run check`

| Правило | Ошибка |
|---|---|
| Файл читается, поля из таблицы, нет лишних | неизвестное поле, неверный тип |
| `id` равен имени файла | `id ... должен совпадать с именем файла` |
| Каждый плагин есть в каталоге | `плагина ... нет в каталоге` |
| `extends` называет существующие бандлы, цикла нет | `цикл в extends: a -> b -> a` |
| У каждого `requires` есть поставщик в составе | `плагин ... требует ..., поставщика в бандле нет` |
| Поставщик подходит по версии контракта | то же: поставщик не той мажорной версии не считается |
| Поставщик `requires` один | `... даёт несколько плагинов`: `requires` берёт одного |
| Бандл не в `planned.json` | `бандл ... уже есть: уберите его из planned.json` |

`optional` и `consumes` необязательны: если поставщика `optional` в составе нет, это заметка в выводе, а не ошибка. Версии сверяются по правилам манифеста ядра: `*`, префикс (`1`, `1.2`), `^1.4`, `~2.3`; поставщик объявляет `1.1`, список версий или `{ "version": ... }`.

:::caution[Это предпроверка]
Граф контрактов строит ядро при загрузке и решает окончательно. Проверка репозитория не знает про `guard`, кратность `consumes` и права: она нужна, чтобы ошибка состава не доехала до пользователя.
:::

## Результат: bundle.json

Файл рядом с поставкой описывает, что именно собрано:

```json
{
  "format": 1,
  "id": "code-workspace",
  "version": "1.0.0",
  "title": "Работа с кодом",
  "description": "Проекты, дерево файлов, просмотр, git и поиск рядом с сессией.",
  "plugins": [
    { "id": "projects", "version": "1.0.0", "category": "code" },
    { "id": "files", "version": "1.0.0", "category": "code" }
  ],
  "enabled": ["projects", "files"]
}
```

`plugins` - плагины после раскрытия `extends`, с версиями из манифестов. `enabled` - то же списком идентификаторов в порядке включения.

## Результат: config.json

Фрагмент настроек для приложения, который включает весь набор:

```json
{ "plugins": { "enabled": ["projects", "files"] } }
```

Его можно слить в файл пользователя или воркспейса: `plugins.enabled` читает ядро ([«Конфиг и состояние»](https://github.com/dex-it/cyborg-harness/blob/master/docs/guide/features/config-state.md)).

## Версии

Версия бандла не зависит от версий плагинов и ядра. Повышайте её, когда меняется то, что получит пользователь:

| Изменение | Версия бандла |
|---|---|
| Добавлен плагин | минорная |
| Убран плагин или заменён несовместимым | мажорная |
| Только версии внутри плагинов | патч |
