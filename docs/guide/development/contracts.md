Плагины общаются только контрактами `cyborg.*`, и перенос ai-cyborg упирается в то, что пакет `@cyborg-harness/contracts` описывает их частично. Спайк SP-01 ([#7](https://github.com/dex-it/cyborg-plugins/issues/7)) свёл потребность и состояние ядра в проверяемую модель.

## Модель

Файл `plugins/planned-contracts.json` описывает для каждого запланированного плагина, что он даёт (`provides`), требует (`requires`), использует при наличии (`optional`) и собирает у всех (`consumes`), и какие члены нужны каждому контракту. Пока плагина нет в каталоге, его место в графе занимает эта запись; появился плагин - берётся его настоящий `manifest.json`, а запись убирают (проверка не даст оставить обе).

Что проверяется автоматически (`npm run check`, тесты на временных репозиториях):

- у каждого запланированного плагина есть запись, у каждого описанного контракта есть пользователь;
- **каждый запланированный бандл замкнут на модели**: у каждого `requires` есть единственный поставщик нужной мажорной версии (бандлы расширяют друг друга через `extends`, как будут собираться настоящие);
- запись не расходится с каталогом.

Готовая [карта контрактов](/catalog/contracts/) строится из тех же данных и сама заменяется настоящими манифестами.

## Что есть в ядре

В карте `Contracts` пакета контрактов сейчас шесть контрактов:

| Контракт | Что в типах |
|---|---|
| `cyborg.agent` | полностью: `facts`, `launch`, `watch`, `ended`, `history` |
| `cyborg.agent-tool` | полностью: `tools`, `call` |
| `cyborg.session-prompt` | `fragment` |
| `cyborg.tree-decoration` | `marks`, `onChange` |
| `cyborg.git` | черновик: `status`, `onChange` |
| `cyborg.sessions` | черновик 1.1: `onChange`, `reveal` |

## Пробелы

Их находит `npm run contracts:gap` (сверяет модель с типами ядра по исходникам; нужен `npm run harness:link`). На момент спайка:

| Пробел | Что не хватает | Задача в ядре | Блокирует |
|---|---|---|---|
| `cyborg.projects`, `cyborg.project-settings`, `cyborg.editor` описаны в каталоге контрактов, но в типах нет | три контракта целиком | [#256](https://github.com/dex-it/cyborg-harness/issues/256) | M-01, M-09, M-10, M-13, M-17 |
| `cyborg.sessions` | `create`, `send`, `paste`, `labels`, `uses` | [#257](https://github.com/dex-it/cyborg-harness/issues/257) | M-03, M-08, M-13, M-17 |
| `cyborg.git` | `root`, `branch`, `headContent`, `branches`, `switch`, `remotes`, `files` | [#258](https://github.com/dex-it/cyborg-harness/issues/258) | M-08, M-10, M-12, M-13 |
| `cyborg.session-prompt` | явный порядок фрагментов (`order`) | [#259](https://github.com/dex-it/cyborg-harness/issues/259) | M-06 (дословность промпта) |
| Долгоживущий процесс со стримингом | `ctx.os.process.run` ждёт завершения, `pty` смешивает потоки | [#260](https://github.com/dex-it/cyborg-harness/issues/260) | M-05 (SSH) |
| Голосовой ввод | микрофон кадра вида, поток вид - главная часть, сокет-сервер | [#261](https://github.com/dex-it/cyborg-harness/issues/261) | часть M-05 |

Пока контракт не объявлен в пакете, плагин объявляет его тип сам через `declare module '@cyborg-harness/contracts'`, как делает шаблон плагина; общие объявления лежат в каталоге `contracts/` этого репозитория, откуда типы по мере готовности переезжают в пакет ядра.

## Что проверено на настоящем ядре

Тесты `scripts/test/kernel-rules.test.ts` поднимают ядро тест-китом и подтверждают правила, на которых стоит устройство репозитория:

- плагин из поставки (`bundled`) отдаёт `cyborg.projects` и активируется;
- сторонний плагин (не в списке встроенных) с `cyborg.projects` **отвергается**;
- сторонний плагин берёт `cyborg.*` у встроенного поставщика через `requires` и работает;
- сторонний плагин отдаёт контракт своего пространства `acme.*`;
- `requires` без поставщика: потребитель не активируется, причина в журнале.

## Команды

```bash
npm run contracts:gap              # пробелы относительно типов ядра, код 0
npm run contracts:gap -- --strict  # пробел - код 1 (для проверки готовности этапа)
npm run check                      # модель и замкнутость запланированных бандлов
```
