Система такая же, как в [Cyborg Harness](https://dex-it.github.io/cyborg-harness/development/contributing/): работа ведётся задачами в GitHub Issues, у каждой есть уровень, ключ и набор меток. Отличия - только в содержании групп: вместо итераций эпика микроядра здесь этапы переноса, а вместо компонентов ядра - компоненты репозитория плагинов.

## Уровни

| Уровень | Что это | Метка |
|---|---|---|
| Эпик | Зонт над несколькими задачами, сам не делается, декомпозируется | `level: epic` |
| История | Крупная единица работы, закрывается несколькими PR | `level: story` |
| Задача | Единица работы, обычно один PR | `level: task` |
| Подзадача | Часть истории или задачи, отдельным PR не закрывается | `level: subtask` |

Задачи эпика привязаны к нему как подзадачи (sub-issues): список и прогресс видны на странице эпика. У эпика не больше 100 подзадач, поэтому хвосты (остатки ревью, техдолг) вешают на отдельную задачу-контейнер.

## Названия и ключи

Эпик называется `[EPIC] Название`. Задача - `[Stage N] [КЛЮЧ] Название`: этап и стабильный ключ, по которому задачи ссылаются друг на друга.

| Префикс | Группа |
|---|---|
| `D-` | Решения владельца, блокирующие работу |
| `SP-` | Спайки: короткие исследования, результат - вывод, а не код |
| `R-` | Репозиторий и инструменты: фикстуры, проверки, CI |
| `M-` | Перенос плагина: один плагин или его самостоятельная часть |
| `B-` | Бандлы: сборка набора, проверка полноты |
| `V-` | Сверка и выпуск: паритет, бюджеты, приложение, вывод старого из эксплуатации |
| `T-` | Технический долг и остатки |

Тело задачи устроено одинаково: «Зачем», «Что сделать», «Где в коде и документах», «Критерии приёмки», «Зависимости и параллельность», «Размер и этап», «Риски и вопросы», «Не входит в задачу». Задача закрыта, когда выполнены все пункты «Критериев приёмки», а не когда слит код.

## Группы меток

Метки работают группами `префикс: значение`. Полный набор - файл [`.github/labels.json`](https://github.com/dex-it/cyborg-plugins/blob/master/.github/labels.json).

| Группа | Значения |
|---|---|
| `type:` | `bug`, `feature`, `enhancement`, `refactor`, `research`, `architecture`, `security`, `chore`, `docs`, `deprecation`, `new-plugin`, `plugin-request` |
| `level:` | `epic`, `story`, `task`, `subtask` |
| `component:` | `plugin`, `bundle`, `catalog`, `template`, `tooling`, `site`, `ci`, `docs` |
| `category:` | по одной на категорию каталога: `agents`, `sessions`, `code`, `trackers`, `extensions`, `workbench` |
| `stage:` | `0`-`5`: этапы переноса ai-cyborg ([карта](/development/roadmap/)) |
| `priority:` | `critical` (каталог или сборка бандлов сломаны), `high`, `medium`, `low` |
| `status:` | `todo`, `in progress`, `in review`, `in test`, `done` (ход задачи); `needs-triage`, `needs-info`, `needs-design`, `needs-card`, `needs-version-bump`, `needs-review`, `needs-testing`, `blocked`, `duplicate`, `stale`, `wontfix` |
| `platform:` | `linux`, `macos`, `windows` |
| `effort:` | `s` (до 2 человеко-дней), `m` (3-8), `l` (больше 8, рассмотрите декомпозицию) |

Есть и метки без группы: `breaking-change` (ломает контракт, `id` плагина, состав бандла или формат данных), `regression`, `upstream` (причина в ядре, Electron, `node-pty`, Node или стороннем сервисе), `external-binary` (причина в `git`, `gh`, `glab`, `jira`, `claude`), `credentials`, `dependencies`. Новая задача получает `status: needs-triage`, задача эпика - `status: todo`.

Метка `category:` обязана быть у каждой категории из `plugins/categories.json`: это проверяет `npm run check`, чтобы список категорий и список меток не разошлись. Добавляя категорию, добавьте и метку.

## Вехи

Этапу соответствует веха GitHub с тем же номером: «Этап 0: ...» - «Этап 5: ...». Этап - набор задач, которые можно вести параллельно; следующий начинается, когда закрыты задачи, от которых зависят его первые.

## Файл меток и синхронизация

Набор меток хранится в репозитории, а не только в настройках GitHub: так он воспроизводим и проверяется.

```bash
npm run sync-labels -- --dry-run     # показать, что изменится
npm run sync-labels                  # создать недостающие, обновить цвет и описание
npm run sync-labels -- --prune       # ещё и удалить лишние, но только неиспользуемые
```

Нужен `gh` с правом на метки. `--prune` пропускает метку, которую несёт хотя бы одна задача или PR, и говорит об этом. Переименование метки делается вручную (`gh label edit "старое" --name "новое"`) до синхронизации: файл знает только итоговые имена. Формат файла - список объектов `name`, `color` (шесть цифр без `#`), `description` (до 100 знаков); `npm run check` его проверяет.
