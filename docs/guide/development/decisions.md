Владелец поручил исполнителю предположить их самому, поэтому статус каждого - **принято по поручению владельца 2026-11-16**: они действуют, пока владелец не переиграет, а запись в этой странице и в комментарии к задаче показывает, что именно предположено и почему. Решение можно изменить: для каждого названо, что от него зависит.

## 1. Где живёт приложение

**Решение.** Приложение Cyborg на ядре собирается в репозитории [ai-cyborg](https://github.com/dex-it/ai-cyborg): окно, меню, раскладка, слой диалогов, упаковка и подпись. Плагины и бандлы остаются здесь, приложение подтягивает бандл `ai-cyborg` из выпуска этого репозитория как `builtinDir`.

**Почему.** У ai-cyborg есть пользователи, имя, история и подпись; новый репозиторий приложения потерял бы их. Этот репозиторий задуман как нейтральный каталог для сообщества, и оболочка одной команды в нём лишняя.

**Что меняется.** V-05 ([#40](https://github.com/dex-it/cyborg-plugins/issues/40)) ведётся в ai-cyborg на отдельной ветке и сливается в `master`, когда паритет подтверждён (V-01).

## 2. Границы плагинов

**Решение.** Принята таблица [карты переноса](/development/roadmap/): 14 плагинов. `trackers` - один плагин с тремя видами (задачи, MR и PR, «Статус»): `MrsService` построен поверх `TrackersService`, а карточка «Статус» собирает данные всех трёх. `remote-sessions` - отдельный плагин (SSH, демон, голос), потому что у него свой демон, лимиты и жизненный цикл. `viewer` включает запуск файла и Markdown. `agent-shell`, `pin-lock` (стенд ядра) и `trackers-http` - вне эпика, «Позже» (M-21, M-22).

**Почему.** Деление трекеров на шесть плагинов требует контракта провайдера, которого нет; пересматривать после паритета. Плагины `session-notifications` и `claude-extensions` в SAD ядра отдельно не описаны: имена принимаются планом, а строки SAD добавит ядро.

**Что меняется.** Ничего в данных: так уже записано в `plugins/categories.json`.

## 3. Порядок фрагментов промпта

**Решение.** Ядру нужен явный порядок фрагментов `cyborg.session-prompt` (поле `order`, [cyborg-harness#259](https://github.com/dex-it/cyborg-harness/issues/259)). Пока его нет, порядок по id плагина расходится с ai-cyborg (`ISOLATION + SUGGEST`, изоляция первой): расхождение записывается в allowlist матрицы при закрытии FR-9001 с причиной и ссылкой на эту страницу. Фрагмент изоляции переносится дословно.

**Почему.** Требование «тот же промпт байт-в-байт» без явного порядка невыполнимо, а обходить его переименованием плагинов нельзя.

**Что меняется.** M-06 ([#17](https://github.com/dex-it/cyborg-plugins/issues/17)): тест на дословность фрагмента и на порядок, расхождение в allowlist до #259.

## 4. Кнопки от модели

**Решение.** Принять реализацию через MCP-инструмент `cyborg.agent-tool` (плагин `next-actions`) вместо разбора конца хода (`parseSuggestions`). Требования FR-12007 и FR-12008 (кнопки снимаются на следующий запрос, на фоновую работу, на вопрос) остаются и проверяются. Расхождение «источник кнопок» записывается в allowlist.

**Почему.** Это путь ядра (SAD, раздел 5): разбор текста ответа хрупок, инструмент даёт структуру.

**Что меняется.** M-18 ([#32](https://github.com/dex-it/cyborg-plugins/issues/32)): сценарий S4 переопределён.

## 5. Окно «Расширения»

**Решение.** Окно переименовывается в «Расширения Claude Code» (правило ПМ-08 плана ядра), запись в allowlist.

**Почему.** Окно управляет расширениями Claude Code, а не самого Cyborg; прежнее имя вводит в заблуждение. Переименование допустимо, потому что человек ничего не теряет.

**Что меняется.** M-19 ([#33](https://github.com/dex-it/cyborg-plugins/issues/33)): заголовок окна и пункт меню.

## 6. Восстановление сессий `eager`

**Решение.** Автоматическое восстановление сессий после перезапуска приложения не переносится. Остаётся ленивое ручное (`resumeId`, `sessions.restore`), которое в ядре уже есть.

**Почему.** `eager` противоречит non-goal BRD Cyborg (план ядра, 2.1) и требует решения вне переноса.

## 7. Данные пользователей

**Решение.** Подтверждается решение 2026-11-11: Cyborg на Harness начинает с чистого листа. Файл воркспейса, файлы `userData/*` и ключи `localStorage` не переносятся; история сессий Claude Code остаётся в `~/.claude` и доступна.

**Что меняется.** V-06 ([#41](https://github.com/dex-it/cyborg-plugins/issues/41)): инструкция перехода объясняет, что заводить заново. Правила ПМ-11, ПМ-12, ПМ-14 плана ядра сняты.

## 8. Лицензия и подпись

**Лицензия.** Предположение исполнителя: MIT (разрешающая, привычная для плагинов, не мешает сообществу). **Файл `LICENSE` не добавлен**: лицензия - юридическое решение, его принимает владелец; до этого README и сайт говорят «лицензия не выбрана».

**Подпись macOS.** Developer ID и нотаризация - решение с расходом для V-05. Пока подписи нет, сборки неподписанные (ad hoc) для разработки; клик по уведомлению (M-07) и запуск из Dock проверяются человеком после подписи.

**Выпуски бандлов.** Публичные релизы GitHub этого публичного репозитория.

## 9. Бюджеты

**Решение.** Старт и память не хуже базы ai-cyborg на 10% по медиане пяти прогонов; процессы главного окна и рендерера сравниваются отдельно от процессов хостов плагинов (они добавляют около 27 МиБ на хост). Бюджеты ядра остаются: вызов через шлюз `ctx.os` не более 1 мс на p99 до 64 КиБ, событие `fs.watch` не позже 5 мс на p99, вывод терминала не более 16 мс.

**Что меняется.** V-04 ([#39](https://github.com/dex-it/cyborg-plugins/issues/39)): допуск записан, расхождение сверх него - решение владельца.

## 10. Заморозка ai-cyborg

**Решение.** Якорь переноса - коммит `6fd308f` ai-cyborg (2026-11-16). Новые **функции** ai-cyborg после якоря в перенос эпика не входят: они заводятся хвостовыми задачами `T-` по мере появления и добавляются в матрицу паритета. Исправления ошибок в ai-cyborg разрешены. Каждое изменение проверяет `npm run parity`: новое в коде получает владельца, а не теряется (CI клонирует ai-cyborg на якоре, а сдвиг якоря - осознанное действие).

**Почему.** За неделю до якоря ai-cyborg получил 15 каналов, 3 события и 31 требование: без якоря перенос гонится за мишенью.

## 11. Типы `cyborg.*`, которых нет в ядре

**Решение.** Пока контракт не объявлен в `@cyborg-harness/contracts` ([карта контрактов](/development/contracts/): `cyborg.projects`, `cyborg.project-settings`, `cyborg.editor`), плагин объявляет его тип сам через `declare module '@cyborg-harness/contracts'` (как шаблон плагина), общие объявления лежат в `contracts/` этого репозитория (пакет `@cyborg-plugins/contracts`, появился с M-01) и переезжают в пакет ядра по мере готовности.

**Почему.** Это не блокирует M-01 на задаче в другом репозитории. Правило ядра запрещает отдавать `cyborg.*` только плагинам вне поставки; объявлять типы можно.

## 12. Голосовой ввод

**Решение.** Голос (`mic:*`, `/voice`) переносится последним внутри M-05 ([#16](https://github.com/dex-it/cyborg-plugins/issues/16)). Если ядро не готово ([cyborg-harness#261](https://github.com/dex-it/cyborg-harness/issues/261)), он выносится в хвостовую задачу, а прочие возможности удалённых сессий не ждут.

## 13. MCP-сервер сессий: токены, поручение вкладке, плагин Claude Code

**Решение.**

1. **Токены сессий хранит и отзывает плагин `sessions`**, и только в памяти (класс `Tokens`): токен выдаётся при запуске сессии, отзывается при выходе процесса, закрытии вкладки (человеком или инструментом `close_session`) и неудачном запуске. Агенту токен идёт переменной окружения процесса (`CYBORG_MCP_TOKEN`, названа в правилах `pty` и `launch`), конфиг MCP содержит адрес и ссылку `Bearer ${CYBORG_MCP_TOKEN}`. Токена нет в аргументах командной строки, файлах данных, журнале, `config`, `state` и документах: файл `0600` из ai-cyborg не нужен (шлюз ядра права файла и не задаёт).
2. **Поручение вкладке остаётся с одноразовым ключом, но вкладку открывает сам плагин.** В ai-cyborg ключ шёл окну, и оно создавало вкладку; на ядре документы-вкладки создаёт `sessions`, окно для этого не нужно. Ключ и промпт поручения не покидают плагин, виду уходят только сообщения `session:handoff` и `session:close` с номерами сессий, а отказ открыть вкладку возвращается модели с причиной (канал `session:handoffFailed`).
3. **Плагин Claude Code `cyborg`** (скилл `parallel-sessions`, хук `lsp-reap`) лежит в `assets/` плагина `sessions` (решение SP-02), записывается при активации в каталог данных и подключается сессиям ключом `--plugin-dir=<каталог>` в аргументах запуска, а не переменной `CYBORG_PLUGIN`: переменная потребовала бы правки скрипта и правила `launch` у `agent-claude-code`.
4. **Итог дочерней сессии без открывшей** показывается уведомлением рабочего стола (право `notify` у `sessions`), как в ai-cyborg.

**Почему.** Сервер MCP принимает вызовы от агента, который работает с правами человека: токен - единственное, что отделяет сессию Cyborg от любой программы на машине, поэтому его держат так, чтобы он не мог утечь через файл, журнал или процессный список. Хранить его постоянно незачем: порт сервера выбирает ОС, и после перезапуска хоста плагина прежний токен всё равно указывал бы на несуществующий адрес.

**Что меняется.** M-04 ([#15](https://github.com/dex-it/cyborg-plugins/issues/15)). Открыто для M-05 ([#16](https://github.com/dex-it/cyborg-plugins/issues/16)): туннель MCP к удалённому хосту должен получить токен удалённой сессии у `sessions`; в контракте `cyborg.sessions` для этого члена пока нет. Открыто для ядра: стабильный порт `serve` (или переподключение), чтобы подхваченные сессии не теряли MCP после перезапуска хоста плагина.
