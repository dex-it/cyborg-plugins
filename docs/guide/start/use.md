Приложение на ядре получает плагины двумя путями: **встроенные** лежат в каталоге поставки приложения, **сторонние** пользователь кладёт в свой каталог плагинов. Бандлы этого репозитория рассчитаны на первый путь.

## Встроенные: поставка

`npm run bundle -- <id>` собирает каталог, который приложение указывает адаптеру ядра как `builtinDir`:

```text
dist/bundles/ai-cyborg/
  bundle.json          состав бандла и версии плагинов
  config.json          { "plugins": { "enabled": [...] } }
  delivery/
    delivery.json      контрольные суммы файлов всех плагинов
    sessions/          результат cyborg-plugin build: manifest.json, index.mjs, ui/...
    files/
    ...
```

Дальше приложение делает то, что и для любой поставки ядра:

1. Копирует `delivery/` в сборку приложения (в упакованном приложении - внутрь `app.asar`).
2. Указывает его адаптеру: `builtinDir: path.join(__dirname, 'delivery')`.
3. Включает плагины: `plugins.enabled` в файле настроек (фрагмент лежит в `config.json`).

При старте ядро сверяет файлы с `delivery.json` и сообщает о расхождении в журнал; плагины из поставки получают общий хост `builtin`. Подробности - в странице [«Установка»](https://dex-it.github.io/cyborg-harness/start/install/) документации ядра и в разделе [«Сборка и упаковка»](https://dex-it.github.io/cyborg-harness/authors/packaging/).

:::tip[Бандл не заставляет включать всё]
`plugins.enabled` - обычный список настроек. Бандл задаёт, что есть в поставке и что включено по умолчанию; пользователь и воркспейс могут сузить список, ядро выключит и зависимых.
:::

## Сторонние: каталог пользователя

Плагин можно упаковать отдельно (`cyborg-plugin pack`) и положить в каталог плагинов пользователя. Ограничения:

- каталог читается только при запуске приложения с флагом `--user-plugins`;
- сторонний плагин получает собственный хост и помечен в окне «Плагины Cyborg»;
- **сторонний плагин не может носить `id` из `cyborg.*` и отдавать контракты `cyborg.*`**: эти имена ядро закрепляет за плагинами поставки.

Поэтому плагины, которые дают контракты `cyborg.*` (сессии, файлы, проекты), существуют только как встроенные, то есть через бандл. Свои плагины сообщества выбирают [собственное пространство имён](/authors/namespaces/) и берут чужие контракты через `requires`, `optional` и `consumes`.

## Что ядро проверит само

Бандл проверяется дважды. В этом репозитории - до сборки: плагины существуют, у каждого `requires` есть поставщик нужной мажорной версии в самом бандле, поставщик единственный. На ядре - при загрузке: граф строится заново, и циклы, несовместимые версии и пропавшие поставщики попадают в журнал плагинов. Проверка репозитория упрощённая и ядро не заменяет: она ловит ошибку состава раньше, чем её увидит пользователь.

## Чего пока нет

Приложение не умеет «включить бандл» одной командой и не показывает бандлы в окне плагинов: ядро знает про плагины, а не про бандлы. Этот шаг описан как предложение ядру в разделе [«Что нужно от ядра»](/development/harness/).
