## Корень

| Путь | Что |
|---|---|
| `plugins/` | Все плагины: `plugins/<категория>/<id>/`; перечень категорий - `plugins/categories.json` |
| `bundles/` | Бандлы `bundles/<id>.json` и `planned.json` с запланированными наборами |
| `templates/plugin/` | Шаблон, из которого `npm run new` создаёт плагин |
| `scripts/` | Проверки, сборка бандлов, генерация страниц каталога; тесты - `scripts/test/` |
| `docs/guide/` | Страницы сайта; `docs/guide/catalog/` генерируется |
| `site/` | Сборка сайта (Astro и Starlight) |
| `assets/` | Значок `icon.svg` и источник картинки для соцсетей |
| `.github/` | CI, публикация сайта, релиз, dependabot |

## Почему категории, а не плоский список

Плагинов будет много и от разных авторов: плоский каталог быстро становится неудобным. Каталог по назначению отвечает на вопрос «где искать»: нужен трекер - в `trackers/`, нужен другой агент - в `agents/`.

| Категория | Что в ней |
|---|---|
| `agents` | Движки агентов: чем запускается сессия, как читается её история |
| `sessions` | Сессии и всё вокруг: вкладки, изоляция, уведомления, подсказки шагов |
| `code` | Работа с репозиториями: проекты, файлы, просмотр, git, поиск |
| `trackers` | Задачи, MR и статус из внешних трекеров |
| `extensions` | Расширения самого агента: магазины, скиллы, серверы MCP |
| `workbench` | Удобства окна, не привязанные к предметной области |

Категория определяется только путём. В манифест ядро чужих полей не принимает, поэтому записать категорию в `manifest.json` нельзя, а дублировать её в README незачем. Идентификатор плагина от категории не зависит: он один на весь репозиторий, и плагин можно перенести в другую категорию, не меняя ни одного `id`.

Нужна новая категория - добавьте запись в `plugins/categories.json` (`id`, `title`, `summary`, `planned`). Пустой категории каталога на диске не нужно: он создаётся с первым плагином.

## Каталог плагина

```text
plugins/code/files/
  manifest.json        манифест ядра
  README.md            карточка и описание для людей
  index.ts             главная часть
  contracts.ts         объявления контрактов (только типы)
  config.schema.json   схема раздела config
  ui/                  виды
  test/                тесты на @cyborg-harness/testing
  package.json         скрипты typecheck и test
  tsconfig.json
```

Состав - как у шаблона ядра. Обязательны `manifest.json` и `README.md`; остальное нужно по мере надобности.

## Правила

Их держит `npm run check`; на каждое есть тест.

| Правило | Зачем |
|---|---|
| Каталог плагина лежит в `plugins/<категория>/`, категория названа в `categories.json` | Чтобы дерево и каталог на сайте совпадали |
| Имя каталога равно `id` в манифесте | Один способ найти плагин |
| `id` не занят ядром (`cyborg`, `cyborg.window`, `cyborg.workspace`) и не повторяется в другой категории | Идентификатор общий |
| `version` - `x.y.z`, `engines.cyborg` задан | Ядро откажет иначе |
| В `README.md` есть карточка | Каталог на сайте строится из неё |
| Плагин, ставший готовым, убран из `planned` | Нельзя быть готовым и планируемым одновременно |
| Файлов рядом с каталогами плагинов в категории нет | Категория - только каталоги |
