## Создать

```bash
npm run new -- <категория> <id> ["Название для каталога"]
```

Например:

```bash
npm run new -- trackers my-tracker "Мой трекер"
```

Команда копирует `templates/plugin/` в `plugins/trackers/my-tracker/` и подставляет идентификатор и название. Она откажет, если:

- категории нет в `plugins/categories.json`;
- `id` уже занят в любой категории;
- `id` недопустим (не строчные латинские буквы, цифры и дефис) или зарезервирован ядром.

## Что получится

Рабочий плагин-пример: контракт `<id>.greeting`, команда `<id>.hello`, сочетание клавиш, раздел `config` со схемой, вид с кнопкой и тест на тест-ките ядра. Он сразу проходит все проверки, поэтому от него удобно отталкиваться: меняйте поведение, пока всё остаётся зелёным.

| Файл | Что делать |
|---|---|
| `manifest.json` | Заменить контракты, команды, права и вид на свои; `engines.cyborg` оставить |
| `contracts.ts` | Объявить свои контракты. Это только типы: потребитель берёт их через `import type` |
| `index.ts` | Главная часть: `activate(ctx)`. Только `@cyborg-harness/contracts` и свои модули |
| `ui/ui.ts` | Вид. Браузерный код без Node, npm-пакеты разрешены |
| `test/plugin.test.ts` | Тесты на `startKernel`: проверка состава, активация, контракты, вид |
| `README.md` | Карточка и описание, [формат](/authors/card/) |

:::tip[Тест-потребитель]
В `test/consumer/` лежит плагин, который только для теста берёт ваш контракт: так проверяется, что поставщика реально можно использовать. В поставку и каталог он не входит, потому что лежит в `test/`.
:::

## До pull request

```bash
npm run check             # раскладка, карточка, бандлы
npm run check:plugins     # cyborg-plugin check: импорты, права, версия API
npm run typecheck
npm test
npm run docs:catalog      # страница плагина для сайта
```

Если плагин был в `planned` своей категории (`plugins/categories.json`), удалите запись оттуда: проверка не даст оставить плагин и в каталоге, и в планах.

Хотите, чтобы плагин ставился пачкой с другими, добавьте его в существующий бандл или заведите свой: [формат бандла](/bundles/format/).

## Pull request

Откройте pull request в `master`. В описании: что делает плагин, какие контракты даёт и берёт, какие права просит и зачем, какие внешние программы нужны. CI соберёт ядро, прогонит все проверки на macOS и Linux и построит сайт; страница вашего плагина появится в каталоге после слияния.
