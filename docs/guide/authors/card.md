---
title: "Карточка плагина"
description: "Шапка README.md плагина: поля, статусы, правила текста и что из неё попадает на сайт."
---

Манифест ядра не принимает чужих полей, поэтому всё, что нужно людям и каталогу, живёт в шапке `README.md` плагина. Это карточка.

```markdown
---
title: Дерево файлов
summary: Дерево файлов сессии с отметками git
status: beta
tags: [файлы, git]
needs: [git]
---

## Что делает

Показывает дерево каталога сессии...
```

## Поля

| Поле | Обязательно | Что |
|---|---|---|
| `title` | да | Название в каталоге и заголовок страницы плагина |
| `summary` | да | Одна фраза о том, что плагин даёт человеку; попадает в таблицы и описание страницы |
| `status` | да | `experimental`, `beta` или `stable` |
| `tags` | нет | Список в квадратных скобках: `[а, б]` |
| `needs` | нет | Внешние программы, которые должны быть на машине: `[git, gh]` |

Шапка - не полный YAML: только строки `ключ: значение`, списки в одну строку в квадратных скобках, значения можно брать в кавычки. Неизвестное поле - ошибка, так опечатка не пройдёт незамеченной.

## Статусы

| Статус | Что обещает автор |
|---|---|
| `experimental` | Работает, но поведение и настройки ещё меняются |
| `beta` | Поведение устоялось, ищем ошибки на живых задачах |
| `stable` | Изменения совместимы, ломающие выходят отдельной мажорной версией |

## Текст после шапки

Он попадает на страницу плагина как есть, под таблицей фактов. Что в нём писать:

- **Что делает** - задача и то, что человек увидит;
- **Контракты и команды** - смысл: зачем контракт и как им пользоваться;
- **Права** - почему без них нельзя;
- **Настройки** - поля `config` и `state`, значения по умолчанию.

Заголовок первого уровня (`# ...`) не пишите: название рисует сайт, начинайте с `##`. Проверка это ловит. Корневые ссылки на страницы сайта пишутся с косой чертой и слэшем в конце (`/bundles/format/`).

## Что сайт строит сам

Из манифеста на странице плагина собирается таблица фактов: идентификатор, версия, контракты (`provides`, `requires`, `optional`, `consumes`), команды, права, ссылка на исходники. Руками их не повторяйте: они не разойдутся с манифестом.

Страницы строит сборка сайта (`npm run build` в `site/`, локально `npm run docs:catalog`); в git они не лежат, поэтому коммитить нужно только карточку и манифест.
