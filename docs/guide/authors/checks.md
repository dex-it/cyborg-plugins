Проверок несколько, потому что каждая отвечает за свой слой: репозиторий, плагин, код, поведение.

| Команда | Слой | Что ловит |
|---|---|---|
| `npm run check` | Репозиторий | Раскладка, карточки README, поля манифеста, нужные каталогу, бандлы и их полнота |
| `npm run check:plugins` | Плагин | `cyborg-plugin check`: манифест по правилам ядра, версия API, импорты, права |
| `npm run typecheck` | Код | Типы скриптов и каждого плагина |
| `npm test` | Поведение | Тесты скриптов и тесты каждого плагина на тест-ките ядра |
| `npm run build` в `site/` | Документация | Сайт собирается вместе со страницами каталога, битая ссылка или якорь - ошибка `verify` |

## Что `check` не делает

Он читает `manifest.json` и `README.md` и не запускает код. Полный разбор манифеста (допустимые права, схемы аргументов, форма контрактов) делает ядро в `check:plugins`: поэтому плагин проходит обе проверки, а не одну.

## Проверка полноты бандлов

Для каждого бандла: все плагины существуют, у каждого `requires` есть единственный поставщик нужной мажорной версии. Правила и сообщения - на странице [«Формат бандла»](/bundles/format/). Пока бандлов нет, шаг ничего не делает, но тесты на нём идут на временных репозиториях.

## Тесты плагина

Тесты пишутся на `@cyborg-harness/testing`: `startKernel` поднимает ядро на самом плагине, `memoryStore` подставляет настройки, `fakePty` - терминал. Шаблон ядра содержит образец на шесть случаев: состав, активация, раздел `config`, контракт, вид. Ядро берётся из собранного клона через `npm run harness:link`; после выпуска пакетов - из npm.

## CI

Каждый pull request и push в `master` проходят `ci.yml` на macOS и Linux: сборка ядра, `check`, `check:plugins`, типы, тесты, сверка страниц каталога, сборка всех бандлов. Сайт собирается отдельно (`docs-site.yml`). Подробности - [«CI и релизы»](/development/ci/).
