Плагины ai-cyborg живут на внешних программах: `claude`, `gh`, `glab`, `jira`, `ssh`, `git`. В тестах настоящие программы не годятся (сеть, вход человека, время), поэтому репозиторий держит общий пакет подставных программ `@cyborg-plugins/fixtures` (каталог `fixtures/`): их перенесли из ai-cyborg и дополнили `glab` и `ssh`. Тест плагина берёт их одной строкой и не копирует.

## Что внутри

| Программа | Что изображает |
|---|---|
| `claude` | `--version`, `plugin ...` (магазины, установка, удаление) и `mcp list`, сессия: событие старта, `cd`, `ask`, `perm`, `suggest`, `flood N`, `trickle N`, `link`, эхо; события хуков пишутся в `CYBORG_EVENTS` |
| `gh`, `glab` | Вход, пользователь, списки задач и MR в формах, которые читает ai-cyborg; число элементов настраивается |
| `jira` | Версия, пользователь, список и карточка задачи SMK-1 в формах `jira-cli` 1.7.0 |
| `ssh` | «Хост» - эта же машина: команда исполняется локально, stdin и код выхода сквозные, туннели `-R` принимаются; свой «дом хоста»; отказ по алиасу |
| `shell` | Подставной `$SHELL`: пропускает `-lc` и login-профиль |
| `git` (медленный) | `rev-parse --show-toplevel` отвечает с задержкой, остальное - в настоящий `git` |

Данные: `claude-home` (`.claude.json` с сервером MCP, личный скилл), `market` (магазин плагинов Claude Code).

## Набор программ

```ts
import { toolbox, fixtureRepo } from '@cyborg-plugins/fixtures';

using box = toolbox({ glab: { host: 'git.corp', items: 5 }, sshFail: 'bad-host' });
box.env;            // окружение: PATH с подставными программами впереди, CYBORG_EVENTS, FAKE_*
box.run('gh', ['api', 'user']);     // запустить программу с этим окружением
box.log('gh');      // что вызывали: строки журнала
box.eventList();    // события хуков подставного claude
```

Каталог набора удаляется при выходе из блока `using`. Параметры: `gh` и `glab` (вход, число элементов, хост), `slowGit` (задержка, секунды), `sshFail` (алиас хоста, который отказывает), `floodOnStart`, `env`.

## Репозитории и каталог настроек

```ts
using repo = fixtureRepo({ branches: ['feature'], dirty: true, remote: 'https://example.com/a/b.git' });
repo.dir;           // настоящий git-репозиторий во временном каталоге
repo.git('status', '--porcelain');

using home = claudeHome();   // копия каталога настроек Claude, которую можно менять
```

Репозиторий создаётся настоящим `git` без хуков и пользовательского конфига, автор - `Fixture`.

## Настройки доходят до программы, даже если её запустил плагин

Ядро передаёт процессам плагина **только** `PATH`, `HOME`, локаль и переменные, названные в правиле `env` манифеста. Поэтому `FAKE_GH=data` из окружения теста до подставного `gh`, запущенного плагином через `ctx.os.process`, не дошло бы. Набор решает это файлом: он копирует программы в свой каталог (`box.bin`), пишет рядом `fake.env` со всеми настройками и ставит этот каталог в `PATH`; скрипты читают `fake.env` при старте, а внешние переменные главнее значений из файла.

```ts
const kernel = await startKernel({
  plugins: [pluginDir],
  os: { env: { PATH: box.env.PATH ?? '', HOME: box.root } },   // только то, что получит настоящий плагин
});
```

Так тест плагина на ядре видит те же подставные программы, что и прямой запуск (`scripts/test` в `fixtures/test/kernel.test.ts`).

## Что проверено на настоящем ядре

`fixtures/test/kernel.test.ts` поднимает ядро тест-китом и запускает через `ctx.os.process` каждую подставную программу: `gh`, `glab`, `jira`, `claude` (сессия с событиями хуков), `ssh` (установка демона скриптом из stdin на подставном хосте, как у `remote-sessions`), медленный `git`. Тот же тест подтверждает, что ядро отклоняет программу вне правил манифеста и флаг из `deny` (`gh api -X POST`) до запуска.

## Записанные сессии

Формат записей для проверки паритета - в `parity/README.md`. Подставные программы выдают всё, что нужно для записи: события хуков, журналы вызовов, вывод.

## Если ядро собрано давно

`npm run harness:link` предупреждает, когда исходники ядра новее его сборки. Тесты на устаревшей сборке идут на устаревшем поведении: сборка двухдневной давности не знала правила `deny`. Пересоберите ядро: `(cd ../cyborg-harness && npm run build:packages)`. `npm install` стирает ссылки на ядро (пакеты ещё не в реестре): после него снова `npm run harness:link`.
